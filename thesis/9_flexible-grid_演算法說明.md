# ⑨ Bast 彈性底格網法（Flexible Base Grids）

> 論文：Hannah Bast, Patrick Brosi & Sabine Storandt (2021). *Metro Maps on Flexible Base Grids*. SSTD '21 (17th International Symposium on Spatial and Temporal Databases), pp. 12–22. https://doi.org/10.1145/3469830.3470899
> 線上結果與工具（flexmaps）：https://octi.informatik.uni-freiburg.de/flexmaps

本文件是給開發者（或其他 LLM）的完整實作指南。讀完本文件後，不需要再看原始論文即可實作。

**與 ⑥ 的關係**：本篇是 ⑥《Metro Maps on Octilinear Grid Graphs》的直接延伸。路由核心——港口節點（8 港口花朵）、彎折邊、sink 邊、成本偏移、ldeg 邊排序、set-to-set Dijkstra、局部搜尋、deg-2 收縮／回插、ILP 形式——**完全沿用 ⑥**，本文件不再重述（見 `6_bast-grid_演算法說明.md`）。⑥ 固定用「鋪滿 padded bounding box 的完整八方向格網」；本篇解掉 ⑥ 的三個缺陷：

1. **格網太大／太冗**：輸入圖稀疏區的格網白費節點，拖慢 ILP 與近似法 → 三種**稀疏底格網**（凸包裁切／四分樹／八向 Hanan 格網），八向格網可縮到 1/5。
2. **版面不彈性**：⑥ 只能畫八方向圖 → 換底格網即換版面：**三角格網 → 六向圖（hexalinear）**、**環放射格網 → orthoradial 圖**。
3. **不保證有解**：⑥ 的近似法可能卡死找不到可行解、且只吃 max degree ≤ 8 的輸入 → **節點分裂**（任意度數都能畫）＋**限制鬆弛**（w∞ 有限大權重，保證一定產出圖）。

## 計算邏輯與程式骨架

> 以下依論文寫「要算什麼、怎麼算」——用虛擬碼、公式與迴圈描述計算步驟。實作時照此邏輯寫；不要呼叫既有程式裡的函式名，也不要寫「call xxx」。

### 1. 輸入（抽象資料）

- 線圖 `G = (V, E, L)`：`V` = 站點集合（各附地理座標）；`E` = 邊集合；`L(e)` = 邊 `e` 上行經的路線識別碼集合（節點可含非站的交叉點）。
- 目標版面 `layout ∈ { octilinear, hexalinear, orthoradial }`。
- 底格網型式 `grid_type`：octilinear 可選 `full｜convex_hull｜quadtree｜hanan(k 次迭代)`；hexalinear 用三角格網；orthoradial 用 pseudo orthoradial 格網。
- 格距 `d`（= 輸入圖相鄰站平均距離，沿 ⑥；padding `r` 沿 ⑥ 的候選半徑觀念）。
- ⑥ 的全部成本參數（`c_45=2, c_90=1.5, c_135=1, c_180=0, c_h=1, c_m=0.5`，偏移 `a`）。
- 鬆弛權重 `w∞`：有限大常數，取「任何**只走合規邊**的路徑成本上界」再加 1（例如 `w∞ = |Ω| · max_edge_cost + 1`）——合規路徑永遠比一條 w∞ 邊便宜。

### 2. 輸出

- 每站的格網座標 `ψ(v)`、每條輸入邊的格網路徑 `p(e)`（vertex-disjoint；方向依版面：八向／六向／環+射線）。
- 若有鬆弛後仍殘留的交叉：交叉點插入**非站節點**後的最終圖（拓撲以該圖為準，見 §3）。

### 3. 建議內部狀態

| 變數 | 說明 |
|---|---|
| `G_split` | 節點分裂後的輸入圖（分裂記錄 `split_map[v] = [v, v′, v″, …]` 供輸出還原） |
| `S` | 稀疏格網節點集（`S ⊆ Ψ_full`，`Ψ_full` = 對應完整格網的節點集） |
| `Ω_S` | 稀疏格網邊集；每邊帶 `n(e)` = 它在完整格網上「模擬」的邊數（成本保持用） |
| `D_max` | 底格網最大節點度：octilinear 8、hexalinear 6、orthoradial 4 |
| `w∞` | 鬆弛權重（取代 ⑥ 的 ∞ 關閉） |
| `violations` | 路由後仍走了 w∞ 邊的（邊, 位置）清單——要落地成非站交叉節點 |

### 4. 主計算流程

```
──────────────────────────────────────────────────
STEP 0：節點分裂（§2）——輸入度數 > D_max 時
──────────────────────────────────────────────────
for each v ∈ V with deg(v) > D_max：
  repeat until deg(v) ≤ D_max：
    // 邊依環繞順序（順時針）排列：e_1 … e_deg(v)
    keep ← 前 D_max − 1 條邊 e_1 … e_{D_max−1}      // 保留在 v 上
    detach ← 其餘邊 e_{D_max} … e_{deg(v)}
    v′ ← 新的「非站節點」，座標 = v 的座標
    把 detach 的每條邊改接到 v′
    新增邊 f = {v′, v}，L(f) ← ∪_{e ∈ detach} L(e)   // 合併路線集合
    // 若 v′ 度數仍 > D_max，對 v′ 重複同一程序
    v ← v′
// 直覺：把塞不下的邊「捆成一束」經過中繼節點 v′ 進站；
// v′ 不是站，畫圖時只是路徑上的匯流點。
// hexalinear 前一定要跑（D_max=6）；orthoradial 更是（D_max=4）。

──────────────────────────────────────────────────
STEP 1：建底格網（依 grid_type，見關鍵子計算 §5.1–5.5）
──────────────────────────────────────────────────
switch grid_type：
  full          → 同 ⑥（padded bbox 鋪滿）
  convex_hull   → S ← convex_hull_grid(G_split, d, r)
  quadtree      → S ← quadtree_grid(G_split, d, r, t=1)
  hanan(k)      → S ← octilinear_hanan_grid(G_split, d, r, iterations=k)
  triangular    → S ← triangular_grid(bbox(G_split), d)        // 六向
  orthoradial   → S ← pseudo_orthoradial_grid(G_split, d, b=8) // 環放射

// 每個格網節點照 ⑥ 擴成「花」：中心 + D_max 個港口 + sink 邊 + 彎折邊
//（octilinear 8 港口、triangular 6 港口、orthoradial 4 港口，見 §5.6）

──────────────────────────────────────────────────
STEP 2：路徑成本保持權重（§4.4）——稀疏八向格網限定
──────────────────────────────────────────────────
// 稀疏格網的一條邊 e 可能對應完整格網上連續 n 條邊
//（= 收縮了 n−1 個中間節點；收縮節點都是被 180° 直穿）
for each e ∈ Ω_S：
  n ← e 在完整格網上模擬的邊數
  w(e) ← (n − 1) · c_180′ + Σ_{i=1..n} w(ω_i)
// 這樣稀疏格網上的最短路成本 ≈ 完整格網上同路徑的成本，
// 品質可與 full grid 直接比較。
// triangular／orthoradial 不用此式（見 §5.6/5.7 的權重）。

──────────────────────────────────────────────────
STEP 3：路由（沿 ⑥ STEP 3–4）＋限制鬆弛（§3）
──────────────────────────────────────────────────
// 與 ⑥ 完全相同：ldeg 排序 → 逐邊 set-to-set Dijkstra → 定案 → 關資源。
// 唯一差異：⑥ 把「已用節點的彎折/sink 邊、交叉對角邊、破壞環繞順序的
// sink 邊」設成 ∞；本篇改設成 w∞（有限大）：
//   ・任何只走合規邊的路徑 < w∞ → Dijkstra 永遠優先走合規路徑
//   ・真的無合規路徑時，寧可付 w∞ 也會回傳一條路徑 → 不再卡死
// ⑥ 的「失敗 → 隨機重排邊序重試」保留（先重試，重試仍失敗才靠 w∞ 過）。
routed ← ⑥ 的逐邊路由（用 w∞ 取代 ∞）
violations ← { (e, ω) : p(e) 走過權重 = w∞ 的邊 ω }

──────────────────────────────────────────────────
STEP 4：局部搜尋（沿 ⑥ STEP 5）
──────────────────────────────────────────────────
// 與 ⑥ 相同（鄰域 = 站移到相鄰空格、整組拆除重路由）。
// 鬆弛的好處在這裡兌現：局部搜尋常能把 STEP 3 殘留的 w∞ 違規修掉
//（違規邊成本極高 → 任何能消掉它的移動都是大改善）。

──────────────────────────────────────────────────
STEP 5：殘留違規落地（§3, 圖 6）
──────────────────────────────────────────────────
for each 仍殘留的交叉 (p(e_i) × p(e_j))：
  在交叉處插入一個「非站節點」x
  把 p(e_i)、p(e_j) 在 x 處各切成兩段，四段都接上 x
// 之後對重疊段落做線序（line ordering）時以插入後的圖為準——
// 形式上違反了原拓撲，但最終畫出的圖不一定會被讀者感知為錯
//（全部實驗殘留違規共 2 例：Berlin×Quadtree 無密度懲罰 1 例＋Berlin×orthoradial 1 例）。

輸出：ψ(v)（分裂節點沿 split_map 還原歸戶）、p(e)、violations
```

### 5. 關鍵子計算

#### 5.1 convex_hull_grid（凸包裁切格網，§4.1）

```
convex_hull_grid(G, d, r)：
  S_pts ← V 的座標集合
  // 每點向四個軸向外擴 r（padding）
  S′ ← ∪_{p=(x,y)∈S_pts} { (x+r,y), (x−r,y), (x,y+r), (x,y−r) }
  H ← convex_hull(S′)
  S ← { ψ ∈ Ψ_full : ψ 落在 H 內 }   // 只保留凸包內的完整格網節點
  Ω_S ← 兩端都在 S 內的完整格網邊
  return (S, Ω_S)
// 最簡單的稀疏化：平均省 46% 節點、47% 邊；品質幾乎不掉（見 §7）。
```

#### 5.2 quadtree_grid（四分樹格網，§4.2）

```
quadtree_grid(G, d, r, t=1)：
  // 對齊：找最小 i 使邊長 2^i·d 的方箱 B（左下角對齊完整格網左下角）
  // 能涵蓋整個 padded bbox → 所有 cell 尺寸都是 d 的倍數，
  // 節點是「格距 d 的完整八向格網」節點的子集（可與 full grid 比較）
  B ← 最小的 2^i·d 方箱 ⊇ padded_bbox(G)
  root_cell ← B
  repeat：
    c ← 任一「含 > t 個輸入點且未標記」的 cell（尺寸 l）
    if l/2 < d：把 c 標記為不再分裂，continue（維持最小格距 d，其他 cell 照常處理）
    把 c 均分成 4 個 l/2 子 cell
  until 沒有這樣的 cell
  // 樹狀矩形格網 → 八向化：每個葉 cell 加兩條對角邊
  S ← 所有 cell 角點；Ω_S ← cell 邊 + 葉 cell 對角邊
  return (S, Ω_S)
// 省最多（平均省 80% 邊）但品質掉最多（見 §7）；
// 除非記憶體極度吃緊，否則不建議當預設。
```

#### 5.3 octilinear_hanan_grid（八向 Hanan 格網，§4.3）——本篇新發明

```
octilinear_hanan_grid(G, d, r, iterations=k)：
  // 先把輸入節點吸附到格距 d 的規則格網（保證最小段長）→ G′
  G′ ← snap_to_grid(V 的座標, d)
  S_pts ← G′ 的節點座標
  repeat k 次（Hanan 迭代）：
    // 經典 Hanan 格網 = 過每點畫水平 + 垂直線，交點成節點；
    // 八向版再加：過每點的兩條 45° 對角線
    lines ← ∪_{p ∈ S_pts} { 水平線(p), 垂直線(p), 對角線↗(p), 對角線↘(p) }
    S_pts ← lines 兩兩交點（限制在 padded bbox 內）
  S ← S_pts 對應的完整格網節點；Ω_S ← 沿各線相鄰節點連邊
  return (S, Ω_S)
// 性質：Hanan 格網含 S_pts 的直角最小 Steiner 樹 → 本身就是「原始版示意圖」。
// 節點密度自動貼合輸入圖（密區密、疏區疏）。
// 迭代 1 次（OHG-1）：平均省 69% 邊、品質只掉 1.6%；
// 迭代 2 次（OHG-2）：幾乎已是完整格網（省 0%），沒有意義——用 OHG-1。
```

#### 5.4 triangular_grid（三角格網 → 六向圖，§5.1）

```
triangular_grid(bbox, d)：
  // 等邊三角形鋪滿平面：每個交點恰 6 條三角邊、夾角 60°
  // → 圖上任何路徑自動是 hexalinear（0°/60°/120° 的正負向）
  S ← 三角格點；Ω_S ← 三角邊；每節點 6 個港口
  格網邊權重：一律 1（uniform）
// 注意：三角格網仍有捷徑風險（圖 12.2 有例）——論文明說沿用 [8]（⑥）的
// 彎折成本技術堵捷徑；「均勻權重」是給格網邊的，與堵捷徑是兩件事。
```

#### 5.5 pseudo_orthoradial_grid（偽環放射格網 → orthoradial 圖，§5.2）

```
pseudo_orthoradial_grid(G, d, b=8)：
  center ← 輸入圖中「度數最高」的節點座標（把格網中心對準最大樞紐）
  radius ← 使格網涵蓋 padded bbox 的最小半徑
  // 內圈 b=8 個節點；環半徑每翻倍、節點數也翻倍：
  //   ring1: 8, ring2: 16, ring4: 32, ring8: 64, …
  //（若每一環都固定節點數＝真 orthoradial，外圈會出現巨大留白；
  //  翻倍法使相鄰節點弧距永遠 ≥ π/4·d ≈ 0.785d，圖面密度近似均勻）
  // 要嚴格保證最小距離 d，內圈半徑須取 4/π·d——實務上差異可忽略
  nodes ← 各環節點 + 射線交點；每節點 4 個港口（環向 2 + 徑向 2）
  optional center node：中心加 1 節點，以正交方式接到第一環的 4 個節點
  //（真實 orthoradial 官方圖常有中心站；接 4 條保持 max degree 4）
  邊權重：徑向邊（環間）等長 → 均勻權重；
          環向邊：第一環均勻權重，外環 × (該環弧段長 / 第一環弧段長)
  return (S, Ω_S)
```

#### 5.6 港口花朵的版面差異（圖 12）

```
octilinear：中心 + 8 港口（沿 ⑥；成本偏移 a 堵住捷徑）
triangular：中心 + 6 港口；彎折成本 60°>120°>180° 遞減同理；
            捷徑風險同樣以 [8] 的彎折成本技術堵（見 §5.4 註）
orthoradial：中心 + 4 港口；只有 90°（環↔射線）與 180°（直行）兩種彎，
            無捷徑問題（4 港口的彎折圖太小，繞不出便宜路徑）
```

#### 5.7 w∞ 的選值與檢驗

```
// w∞ 必須「有限」但大於任何合規路徑成本：
w∞ ← (格網邊數上界 · 最大單邊成本) + 1
// 檢驗：跑完 STEP 3 後掃描所有 p(e)：
//   若 Σ 成本 ≥ w∞ → 該路徑至少踩了一條違規邊，記入 violations
//   （由於 w∞ 遠大於一切，一條路徑踩幾條違規邊都能從總成本反推）
```

## 1. 問題定義與核心理念

⑥ 把畫示意圖化為「底格網圖上的最短路徑組合問題」，但底格網寫死為「鋪滿 padded bounding box 的完整八向格網」。本篇的洞見：**底格網本身是自由參數**——

- 換**節點分佈** → 稀疏格網（大幅縮小問題規模、ILP 記憶體與時間跟著縮）；
- 換**幾何結構** → 換輸出版面（三角格網＝六向圖、環放射格網＝orthoradial 圖），**路由演算法一行不用改**；
- 把「關閉 = ∞」改成「關閉 = w∞（有限大）」→ 演算法從「可能失敗」變成「必然給出一張圖」，殘留違規交給局部搜尋修、修不掉的落地為非站交叉節點。

這是第一個能畫出**滿足 Nöllenburg 全部硬限制**（無交叉、環繞順序不變、最小站距）的 orthoradial 示意圖自動化方法。

## 2. 節點分裂（§2）

底格網的最大節點度限制輸入圖：八向 8、六向 6、環放射 4。真實路網常超過（例：Stuttgart 樞紐站）。分裂程序（圖 5）：保留環繞順序前 `D_max−1` 條邊，其餘邊整捆改接到同位置的新**非站節點** v′，v′ 與 v 之間補一條邊 `f`（`L(f)` = 被移走邊的路線聯集）；v′ 仍超度就對 v′ 遞迴。畫完圖後 v′ 只是線束的匯流點，不畫站符號。

---

## 3. 限制鬆弛（§3）

⑥ 用 ∞ 權重硬性禁止「穿越已用節點、X 交叉、破壞環繞順序」，代價是貪婪路由可能走進死路（隨機重排也救不回）。本篇改用 **w∞**：

- w∞ 夠大 → 有合規路徑時行為與 ⑥ 完全一致；
- 無合規路徑時回傳「付了 w∞ 的違規路徑」而不是失敗；
- 局部搜尋階段違規路徑成本極高，常被自然修掉；
- 修不掉的（全部實驗僅 2 例：Berlin×Quadtree 無密度懲罰、Berlin×orthoradial）：在交叉處插入非站節點，把兩條路徑各切兩段接上（圖 6）——線序處理以插入後的圖為準，最終圖面多數情況看不出違規。

## 4. 稀疏底格網三式（§4）

| 格網 | 做法 | 平均省（節點/邊） | 品質損失（近似法, Table 3） | 建議 |
|---|---|---|---|---|
| Convex Hull | 完整格網裁切到 padded 凸包 | 46% / 47% | **−0.9%（反而更好**，裁掉的區域少了局部最優陷阱） | 首選之一 |
| Quadtree | 一點一 cell 的四分樹＋葉 cell 補對角邊 | — / 80% | +9.3%（加密度懲罰時爆到 +39.7%） | 只在記憶體極緊時用 |
| 八向 Hanan（OHG-1） | 過每點畫水平/垂直/兩對角線，交點成網 | 57% / 69% | +1.6% | 首選之一 |
| 八向 Hanan（OHG-2） | 再迭代一次 | ≈ 0% | 0% | 無意義，等於完整格網 |

ILP 端同趨勢（Table 2：CH +0.6%、Quadtree +9.5%、OHG-1 +1.6%）。**求解時間不一定變快**（稀疏格網的記憶體佈局不規則、鄰居查詢變貴、更難找第一個可行解；Stuttgart/Berlin 的 ILP 反而慢好幾倍）——稀疏格網的**穩定紅利是記憶體**：Sydney ILP 從 28.9 GB（full）降到 8.3 GB（OHG-1）。

**路徑成本保持**（§4.4）：稀疏格網一條邊模擬完整格網 n 條邊（中間節點被 180° 直穿收縮），權重取 `w(e) = (n−1)·c_180′ + Σ w(ωᵢ)`，使稀疏格網上的成本與完整格網可比。

## 7. 實驗結果（§6；AMD FX-8150、Gurobi 9.1.1、五城：Freiburg/Vienna/Stuttgart/Berlin/Sydney）

- **規模**：見 §4 表。ILP 變數規模隨格網等比縮小。
- **品質**：Convex Hull 與 OHG-1 幾乎不損品質（平均 ≤ 1.6%，近似法上凸包甚至 −0.9%）；Quadtree 明顯差（+9.3%，帶密度懲罰 +39.7%）。
- **速度**：八向圖近似法全部 < 0.5 s；六向與 orthoradial 全部 < 2.5 s（近似法平均 594 ms / 791 ms；同網 ILP 要 0.6 h / 1.9 h，近似誤差約 10–13%）。
- **可行性**：鬆弛後所有資料集都產出圖；殘留拓撲違規僅 2 例（Berlin×Quadtree 無密度懲罰 1 例、Berlin×orthoradial 1 例）。

## 8. 實作檢查清單與陷阱

1. **先分裂再路由**：目標版面的 D_max（8/6/4）決定要不要分裂；orthoradial 幾乎每個轉乘站都要分。分裂新增的是**非站節點**，畫圖與標籤都要跳過它。
2. **quadtree 的對齊不可省**：cell 尺寸必須是 d 的倍數、格點必須是完整格網節點的子集，否則成本無法與 full grid 比較（品質評估失真）。
3. **Hanan 格網記得先 snap**：輸入節點先吸附到格距 d 的規則格網再畫線，否則交點間距可能小於最小段長。
4. **成本保持權重只給八向稀疏格網**：三角與環放射有各自的權重規則（均勻／弧長比例），不要套 `(n−1)·c_180` 公式。
5. **w∞ 是「有限大」不是「很大就好」**：太小會讓違規路徑跟合規路徑競爭；太大要留意浮點精度。取「合規成本上界 + 1」並在路由後用總成本 ≥ w∞ 檢出違規。
6. **鬆弛 ≠ 放棄拓撲**：先隨機重排重試（沿 ⑥），重試無效才讓 w∞ 路徑過關；局部搜尋要把「消除 w∞ 邊」視為頭號改善來源。
7. **殘留交叉必須落地**：插入非站節點、切開兩路徑——不落地的話後續線序（line ordering）會在重疊段算錯。
8. **orthoradial 的環向權重**：外環弧段實際較長，權重不乘弧長比例會讓路徑偏好繞外環（圖面出現大迂迴）。
9. **三角格網的捷徑照堵**：三角格網仍有捷徑風險（圖 12.2），論文明說沿用 [8] 的彎折成本技術堵捷徑；格網邊另用均勻權重——兩件事不要混。
10. **選型**：要縮 ILP 記憶體/規模 → Convex Hull 或 OHG-1（品質幾乎不掉）；要六向/環放射風格 → 換底格網即可，路由核心不動；Quadtree 只在極端記憶體壓力下用；OHG-2 以上不要用。
