# 移枝（route-branch-shift）

本文件是該演算法／規格的**規格權威**（系統說明，**不是** skill）。實作必須與它相符。

movewise 四步鏈的**第 3 步**（移點 → 移線 → **移枝** → 併格）；
輸入＝ system note `route-line-compact` 之後的佈局。
實作：`src/stores/movewise.js` 的
`branchShiftPass(skeleton, cells, cols, rows, {limit, skip})`（單一掃描 pass）。

## 為什麼要有這一步（2026-08-07 使用者裁決）

使用者看新加坡＋LRT 的程式網絡循環結果，指著右上角吊在外面的兩團 LRT 環線說
「其實可以向左下移動，有可能可以優化嗎」。可以——而且**三個既有階段一個都做不到**：

| 階段 | 為什麼搬不動那團 |
|---|---|
| 移點 | 一次動一個頂點。動團裡任何一點都會折彎團自己的 H/V 邊 → `STRICT_NO_BEND` 否決。 |
| 移線 | 搬的是同軸直線元件（`lineComponents`）。環是 H 邊＋V 邊混成，搬水平那半必然拉斜垂直邊 → `hv < 0` 否決。 |
| 併格 | 只刪「整列／整欄都空」的空帶。那片空白所在的列與欄別處有點占著，一條都刪不掉。 |

缺的自由度是「**整團一起搬**」。剛體平移下團內部完全不變，唯一改變的是那條把團
接回網絡的邊——正好就是使用者看到的那一個自由度。機制早就在
（`makeMover` 的 `validShift`／`applyShift` 本來就是給剛體群集用的），
這一步只是把「群集怎麼切出來」補上，**沒有新增任何硬規則、也沒有放寬任何一條**。

## 規則

- **分枝**＝橋（cut edge，拿掉就讓圖多一個連通分量的段）切出的一側頂點集合
  （`bridgeSegs` ＋ `branchSideOf`）。橋用 iterative Tarjan 找（遞迴版在紐約規模會爆堆疊）；
  平行邊（同一對頂點兩條段）不會被判成橋——回邊只跳過**同一個** seg 索引。
- **兩側都收**（一座橋給兩個候選），但排除兩種沒有意義的：
  - 一側只有 1 個頂點 → 那是葉節點，**移點**已經在管（而且移點另有消交叉優先等
    自由度，這裡收了只是兩邊搶同一個點）。
  - 另一側只剩 ≤1 個頂點 → 等於整張圖平移，相對關係沒變、純粹浪費。
- **順序固定**為（成員數, 最小 id），**不吃插入序**——結果必須是決定性的
  （落檔內容與 `checkFrameParity` 都靠這個）。串在一起的橋會切出同一團，
  以整份成員當 key 去重。
- **八方向各 ±1 格**（`DIRS8`，一次一格）。
- **採納條件與移線完全共用**（`rigidShiftCandidates`）：
  1. **邊界段 H/V 淨增 > 0**（`boundaryHvDelta`）——優先挑淨增最大者。
  2. 若都沒有，但**邊界段總長變短**（`-boundaryLenDelta > 1e-9`）——挑縮最多者。
  3. 同分時再挑「同路線比較直」的方向（彎折成本，只排序不採納；見 `route-endpoint-move`）。
  另需通過：`boundaryKeepsHV`（逐段不准折彎）＋`boundaryKeepsStraight`（頂點層直穿
  不可變轉角）＋ system note `route-span-cap`（`boundarySpanOk`）＋`validShift` 硬規則
  （不壓點／不新增交叉／象限與邊環繞序不變）。
  - 只需檢查**邊界段**：剛體平移下，兩端同動與兩端全靜態的段都保持原相對幾何。
    對分枝而言邊界段通常只有一條——那條橋。
  - 橋常常是「上游帶進來的長段」（如新加坡那條長對角），跨距一開始就超過上限；
    `spanOk` 的舊長段豁免（只准縮短或不變）正好讓它可以被拉近，不會一開始就死鎖。

## 實測（2026-08-07）

對磁碟上 188 組已落檔的程式網絡循環結果重跑新的四階段循環：

| | |
|---|---|
| 網格面積合計 | **−9,801 格** |
| H/V（水平垂直段數）合計 | **+268**（變多＝更直） |
| 變差的組數 | **0** |

單城例：新加坡＋LRT `algorithm-flex` 22×20 → 19×16（面積 440 → 304，−31%），
H/V 106 不變（一條直線都沒被折彎）；紐約＋地標 `algorithm-sat` 1209 → 1036、H/V 170 → 174。

## 收斂

每一步都讓 (−H/V 數, 邊界總長) 以**字典序**嚴格下降 → 有界，因此必然終止
（與 system note `route-line-compact` 同一套位能函數）。
循環端另把移枝納入 stop-thrash 的「還在進展嗎」判斷（`!branch.stats.moved`），
否則正在縮小網格的城會被提早砍掉。
