Adapt-Metro 系統架構

本頁以 C4 模型與 UML（元件圖、類別圖、狀態機、序列圖、ER 圖）完整描述 Adapt-Metro 的系統架構： Vue 3 單頁應用、Vite dev server 中介層、Node.js 資料管線、agent CLI（Claude Code／Cursor Agent）LLM 整合， 以及「1 RAW MAPS（抓圖＋骨架化）→ 2 GRIDDING（網格化）→ 3 STRAIGHTENING → 4 FRAME MAPS」四階段示意圖佈局演算法管線 （step 代碼＝磁碟資料夾名：1-raw-maps〜4-frame-maps）。 圖中的識別字（檔名、函式、路由）皆與程式碼一一對應，可直接以此頁為 code tour 的入口。

規模：metro 599 系統／5,898 線／37,313 站（index.json）· railway 9 系統（台灣 2＋日本 7）／173 線／4,808 站 · highway 3 都會區／25 線／251 交流道 · 變體：STRAIGHTENING_DIRECTIONS=['orig']（rot 休眠；內建旋轉城市 -l33/-r39 另算）· 佈局權威：maps/{group}/{city}/3-straightening/{來源}/[{模型}/]{鏈}/{子夾}/（一個 json 一個圖）· 命名鐵律：代碼＝tag＝資料夾＝檔名（layerRegistry.js）· stack: Vue 3.5 + Pinia 3 + dockview-vue 7 + 地理底圖 + D3 + Vite 6 · Mermaid 11 · LLM：九鏈 × 13 模型 × 三支 agent CLI（claude／cursor-agent／dsc）· 回歸基準：frameParity 980 組（全球）· 對照日期：2026-08-12

為什麼不再往下拆：核心的 computeStraighteningLayout() 是四階段管線的協調器， 與模組層快取（cachedPost / cachedEndp / cachedLine / cachedGather / cachedLoop / cachedStraighteningBase / stepState …）緊密耦合——抽出去只是把耦合換成一長串參數，可讀性沒有變好， 卻要冒改壞演算法的風險（本專案無測試套件）。已拆出的邊界乾淨模組： d3/buildDrawData.js（純資料轉換）、lib/shapeGuide.js（矩形凍結頂點的 快照／釘回）、lib/headlessRun.js（LLM 功能共用的 run/poll 機構）。

泳道差異：grid 來源跑①〜⑨＋llm；llm-skeleton2grid／llm-working2grid（檔案層按模型拆：orig-llm-*-grid-<model>）來源只跑 llm（＋可選 llmshape 頭圖層），不跑論文①〜⑨（詳 §9b）；llm-working2grid 另加 llm-working2straight。凡有 llm 的泳道另可跑 LLM 網絡循環（llm-network-loop）餵第二張 Frame——**由使用者自行啟動**（面板分頁或 --chain=loop）；直線化跑完接的是**程式網絡循環**（movewise），--chain=align 不隱含 loop。舊稱 cell／map 僅遷移別名。

RULE跨模組不變式與持久化

演算法／資料不變式（違反即 bug）

  • 唯一移動關口：任何演算法要移動節點都必須經 hillClimb.js makeMover；四條硬規則（邊界／象限／遮蔽／邊環繞序）與 FROZEN 檢查都在這一個關口實施。
  • 形狀凍結：LLM 指定形狀成方即餵下游（執行調整已移除）；頂點進入 SQUARE_GUARD（setSquareGuard）；下游可動方形頂點以外的點，但不得破壞形狀約束。唯一暫停旗標＝「重新計算」寫的 shapeFeedCleared。形狀輸入一律 Gridding flow base（不吃前次形狀結果）。
  • SPAN_CAP：移點與移線的每一步，受影響段的兩個非中途站 Chebyshev 距離不得超過上限（預設 4，2026-08-06 由 3 改為 4；單一真相＝src/lib/layoutDefaults.js 的 DEFAULT_SPAN_CAP，樣式 tab 可調＋重新計算套用）。本來就超限的舊長段豁免，所以它不保證輸出跨距 ≤ 上限——真正壓低跨距的是併格。
  • DRIFT_CAP：四個 pass 的候選都不得離「循環輸入」這個錨點超過 0.20（正規化 [0,1]² 的歐氏距離）；剛體平移要求每個成員都在上限內。是上限不是懲罰項，收斂論證不受影響。
  • paper fidelity：直線化演算法照 data/thesis 論文 md 實作、不自創；只算非中途站，中途站事後平均放回。命名＝①〜⑨＋LLM 直線化（＋LLM 骨架地圖網格化來源軸）；矩形不是 #9。
  • 嚴格改善：論文鏈的逐批套用（finishBatches strict）只接受 scoreAlign 變好的批次——HV 優先、45° 次之。
  • LLM 套用規則（2026-07-30）：align 有結果即套用；rect 成方即餵（可資料流代跑）；grid／eval 寫檔＋顯示，等「執行調整」切換；其餘 LLM 鏈只由面板按鈕啟動。絕不手改結果檔。
