04城市判定與合併CITY RESOLUTION

「同一城市＝同一系統」的三層防護

SKILLmetro-osm-fetch城市規則metro-cities

OSM 車站常無 network 標籤，城市名稱解析容易撞名（如 S-Bahn Frankfurt 的 bahn token 撞上 Berlin U-Bahn）——三層護欄避免抓錯城市。

1 · token 黑名單

泛用交通詞（bahn／ubahn／sbahn／lrt／tram／verkehrsverbund…）不得參與城市名稱比對。

2 · rebucket 距離護欄

member network 解析出的目標城市，須離群組重心 ≤250 km 才准搬家；全國性營運商（如 DB）重心無意義。

3 · 線級距離護欄

解析出的 wiki 城市離該線重心 >250 km ⇒ 改用線自身座標或原始反查城市，自成獨立系統檔。

都會圈合併 CITY_MERGE

鄰接行政市併成一城一檔（如桃園→台北）；被併城市在驗證時以 covered_by 標註通過。

LRT 範圍規則

附掛輕軌的城市（台北／高雄／新加坡）附加收錄；整系統即為 LRT tagging 者（Vancouver SkyTrain）全收；純附掛輕軌原則剔除，但覆蓋率 <0.6 時例外保留。

一份 FeatureCollection：系統中繼資料＋兩種 feature

每座城市一個 GeoJSON（城市樹：maps/{groupId}/{cityId}/1-raw-maps/working/{cityId}-1-raw-maps-working.geojson；舊 networks/／metro-maps/／systems/ 寫法讀取時改寫）：頂層掛 metro_system，features 只有兩種——車站 Point 與 路段 MultiLineString。工作地圖（working）與原始地圖（source，唯讀 OSM 備份）必須一模一樣。operator／wikidata 欄位已全面移除（features＋metro_system＋index.json）；wikipedia／official_website 保留。

{ "type": "FeatureCollection", "metro_system": { "continent": "asia", "country": "Taiwan", "city": "Taipei", "official_website": "…", "wikipedia": "…", "line_count": 18, "segment_count": 20, "station_count": 197, "audit": { …逐城驗證結果 } }, "features": [ { …Point 車站 }, { …MultiLineString 路段 } ] }
幾何語意 1

線永遠壓在站點上：路段幾何＝共站合併後的車站點依站序連線，每個折點、端點都是車站（跳站特快段例外，見 Stage 2）。

幾何語意 2

重疊路段只畫一條：相鄰車站對被多線共用時只輸出一個 feature，routes list 記行經路線——一條 route 的完整路徑＝所有含它的路段之聯集。

幾何語意 3

快車一律不抓：只跳站的快車（站點是慢車子集）不另成線——各停已涵蓋全部車站；像紐約 J/Z 交錯停站或獨立編號快線（香港 AEL）自然保留，跳過的站沿慢車走廊標 pass 畫共線。

29方向級與候選選擇序DIRECTION LEVELS & PICKBEST

任意／4／8／16 方向：能用低一級就不用高一級

SKILLroute-frame-draw

工具列「方向」下拉四選一（預設 8），四個方向級同一套判斷邏輯，差別只在允許的腿方向集合。方向級優先是 tie-break 不是硬閘：衝突數（含近距貼線）排在方向級之前——零衝突的 22.5° 贏過有重疊或貼線的 45°；兩者都乾淨時 45° 一定優先。決勝序 H/V → 45° → 22.5° → 任意角。

＋45°。本節所述的完整候選折線規則。

16 方向（＋22.5°/67.5°）

35c兩類求解者ALGORITHM vs LLM

固定演算法與 LLM：各自的不可替代之處

系統同時保有兩類求解者——九條確定性演算法鏈與LLM 鏈（九條功能；直線對照命名上含 LLM 直線化＋LLM 骨架地圖網格化）——吃同一輸入、受同一 harness、以同一組指標量測。差異不來自資料或評分標準，只來自求解者本身。關鍵前提：九個 LLM 功能沒有一個是固定演算法，系統固定的只有脈絡 schema、硬規則驗證器與結果檔格式，求解策略每次由模型自行構思。

它是下界，也是唯一的基準

提供與模型無關的品質保證；也是 LLM 唯一可靠的比較對象。只有毫秒級確定性鏈跑得動 599 系統全量比較（目前變體＝orig）。

LLM 不可替代

它能用沒被寫進規格的先驗

排名吸附的 H/V 段數結構性為零（每個相異座標各配一欄，兩點永遠不同欄）。模型看出「這兩站幾乎同一條經線，該段其實是正南向」而把它們指進同一欄——這只需要「距離重要」這個先驗，而它從未被寫進排名吸附的規格。

選用準則：目標可形式化、需全量、需程序級可重現 → 演算法；目標涉及難以形式化的判斷或使用者當下意圖 → LLM；兩者皆置於同一 harness 之下，使正確性不隨選擇而變。模型策略若反覆收斂（如「保距量化＋貪心吸附」），就循觀察—固化寫成程式碼，從右欄移到左欄。

41四步鏈的定位POSITIONING

犧牲最佳性，換取秒級速度與逐步可視化

固定拓撲下的正交示意化＋面積最小化是經典 NP-hard 問題——TSM 框架的 orthogonal compaction、VLSI 1-D compaction、Misue et al. 的 orthogonal ordering 保持都是零件級近親。

本系統的做法

Local search，非求解器

每種移動各守一個嚴格單調不變式，且每個移動後立即全域壓縮（movewise）——用局部搜尋逼近最佳解，不依賴 ILP／SAT 求解器。

換到的東西

秒級全量速度＋逐步可視化

全量約 5 秒收斂（599 系統）；犧牲最佳性換取速度，且每一個單一移動都可以在逐步驗證裡重播、比對前後——這是求解器路線（ILP/SAT）給不了的。
